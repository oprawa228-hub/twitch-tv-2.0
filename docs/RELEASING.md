# Выпуск обновления

Пакет `com.oprawa.twitch20` и постоянный сертификат сохраняются. Закрытый ключ находится вне репозитория: `C:\Users\Opraw\.android\signing\twitch20\release.jks`, резервная копия — `D:\Private-Backups\Twitch20-signing`. Пароли находятся в локальных исключённых файлах. Не публикуйте эти каталоги и не заменяйте ключ.

1. Проверьте изменения, относящиеся к ним тесты и работу release APK на Android TV. Управление общим устройством и выпуском выполняет один ответственный.
2. Сверьте последние опубликованные версии и `updates/test.json`, затем увеличьте `releaseCode` и задайте новое `releaseName`. На начало beta.11 публичный выпуск — beta.10/code12. Команда сборки кандидата с JDK17: `./gradlew.bat :app:assembleRelease '-PreleaseCode=13' '-PreleaseName=0.1.0-beta.11' --no-daemon`. Сам факт сборки не подтверждает публикацию.
3. Выполните `python tools/stage_release.py app/build/outputs/apk/release/app-release.apk`. Скрипт проверяет пакет и сертификат, создаёт APK, `update.json`, `SHA256SUMS.txt` в `dist/v<versionName>` и запрещает замену отличающегося артефакта той же версии. Для apksigner нужен JAVA_HOME и локальный Android SDK из README.
4. Опубликуйте проверенные исходники; создайте GitHub Release с тегом соответствующего коммита и тремя файлами из каталога кандидата. Для беты включите prerelease. Уже опубликованный APK не перезаписывайте.
5. Скачайте APK по публичной ссылке и сравните SHA-256. Только после успешной публикации перенесите его `update.json` в `updates/test.json`. Для обычного стабильного выпуска добавьте `updates/stable.json`, опубликуйте обычный release и проверьте GitHub Latest. Сейчас стабильного релиза нет.
6. На предыдущей подписанной версии выберите нужный канал, проверьте, скачайте и подтвердите обновление системным установщиком. Разрешение установки из этого приложения выдаётся один раз; если Android закрыл приложение, откройте его и повторите проверку/загрузку.
7. Сверьте установленный APK с опубликованным, версию, настройки, историю и аккаунт. Запишите устройство, результаты и ограничения в TEST_RESULTS/HANDOFF. `adb install` не заменяет проверку OTA.

GitHub Release API — основной источник; при 403/429 приложение использует закреплённый JSON в этом же репозитории. Метаданные всегда ссылаются на неизменяемый APK конкретного релиза. Личный GitHub-токен приложению не нужен. Секретов CI нет: сборка и подпись выполняются локально.

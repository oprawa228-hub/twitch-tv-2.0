# Объём и решения

Основной объём соответствует TASK.txt: каталог/категории/поиск/канал; DCF аккаунт/отслеживаемые; эфир/VOD/клипы; качество/seek/resume; чат overlay/theater; настройки с живым примером; проверенные обновления.

Дополнения:
- Гостевой доступ включён через недокументированную Twitch web интеграцию; работоспособность проверяется отдельно от официального OAuth.
- Предпросмотр видео карточек отложен до измерений: первая версия не создаёт скрытые видеосессии.
- Кадры при перемотке отложены: обязательны рабочая перемотка и позиция; storyboard endpoint нестабилен.
- Уведомления о новых эфирах отложены: требуют отдельного foreground/background и EventSub/polling решения.
- Дополнительные эмоты/анимированные Twitch-эмоты отложены; первая версия читает текст чата, имена и цвета.
- Отправка чата, мультипросмотр и перенос старых настроек вне обязательного первого выпуска.
- Каталоги первоначально загружают первую страницу; pagination необходима для больших персональных списков, учитывать в финальном объёме.
- Subscriber-only источники/Turbo не гарантированы собственным OAuth Device Flow; не обходить access controls. Публичное видео проверяется на настоящем Twitch.

Реальная реализация хранения: небольшие настройки и capped resume positions в SharedPreferences (apply), токены в AtomicFile+AndroidKeyStore AES-GCM. DataStore рассмотрен, но добавление зависимости пока не даёт необходимого выигрыша этому размеру состояния. Полноценная БД не нужна.

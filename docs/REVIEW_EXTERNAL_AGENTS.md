# Оценка присланного AGENTS.md — 2026-11-10

Источник: `C:/Users/Opraw/Downloads/Telegram Desktop/AGENTS.md`, прочитан целиком. Это предложение для оценки, а не замена корневого AGENTS.md и задания `docs/TASK.txt`.

## Что полезно

- Разделять авторизацию, получение источника, воспроизведение и UI. Сбой одного слоя не должен бесконечно перезапускать другой.
- Проверять сетевые ответы и HLS на синтетических/обезличенных фикстурах без Twitch в автоматических тестах. Живые проверки учитывать отдельно.
- Ограничивать повторные запросы, проверять отмену и устаревшие ответы, сохранять паузу и осознанно возвращаться к live edge.
- Не выдавать наличие рекламного DATERANGE за доказательство того, что реклама показывается сейчас. Сопоставлять плейлист, позицию и реальный кадр.
- Не хранить токены и подписанные media URL в логах. Сохранять вход через код и защищённое хранилище Android Keystore.
- Проверять реальные D-pad действия и явно отделять эмулятор от физического телевизора.

Уже существуют `TwitchAuth`/`TokenVault`, изолированный `TwitchRepository`, владелец плеера `PlaybackSession`, тесты HLS diagnostics/progress/recovery, auth lifecycle и чата. Начинать эти подсистемы заново не требуется.

## Что нельзя принимать как готовое решение

1. **Форк Xtra противоречит исходному заданию.** Twitch 2.0 сохраняет собственную реализацию. Xtra можно изучать как внешний пример. При переносе кода нужно учитывать его AGPL-3.0: https://github.com/crackededed/Xtra.
2. **Удаление рекламных сегментов не создаёт отсутствующие сегменты трансляции.** При серверной подмене контента это способно оставить пустое окно. Корректность media sequence, timestamps, discontinuities и ключей нельзя свести к пересчёту длительности. Спецификация HLS: https://datatracker.ietf.org/doc/html/rfc8216.
3. **Перебор playerType не гарантирует чистый источник.** Значения и эффект требуют текущих сравнительных измерений. Бесконечный перебор повышает задержку и число запросов.
4. **Прокси — дополнительная зависимость.** Доступность, передаваемые данные и границы доверия должны быть определены до включения. Автоматически пересылать ему OAuth или подписанный URL недопустимо. Сейчас не добавляется.
5. **Токен аккаунта и доступ к видео — разные проверки.** Собственный Client ID прошёл account validation, но прежний эксперимент получил отказ при запросе видео. Успех legacy-входа подтверждён отдельным сетевым опытом, ещё требуется проверка APK.
6. **Clean/HasAds/Failed недостаточно для живого потока.** Отсутствие маркера в одном ответе не гарантирует отсутствие рекламы позже. Нужны состояния offline, отказа доступа, сети, прогресса окна и ограниченного восстановления. Не вводим обещание «чистый» по одному снимку.
7. **Список библиотек и шесть Gradle-модулей не являются обязательным улучшением.** Apollo, Retrofit, Hilt, Room и Paging добавлять только при конкретной потребности. Само разделение каталогов не исправляет запуск эфира.
8. **Client ID публичен, токен секретен.** Это разные категории. Twitch требует отдельный Client ID для каждого приложения: https://dev.twitch.tv/docs/authentication/register-app/. Legacy-эксперимент остаётся отдельной локальной сборкой.
9. **Проверки зависят от доступного оборудования.** Реальный поток можно наблюдать на доступном эмуляторе. Это не доказательство поведения на физическом ТВ и не гарантия для всех каналов/аккаунтов.

## Принятое действие

Довести контролируемое сравнение на KaiCenat: гостевой запуск → отдельный вход → запуск с аккаунтом → короткая и длинная пауза → повторный Play. Зафиксировать реальный кадр, продвижение HLS, совпадение аккаунта и количество повторных запросов. Не менять публичный канал обновлений по результатам одной проверки.

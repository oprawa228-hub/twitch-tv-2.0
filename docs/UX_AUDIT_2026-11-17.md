# Интерфейс Twitch 2.0 с пульта · 17 ноября 2026

Аудит установленной 0.1.0-beta.13-preview.7 (21). Наиболее заметные возможности для улучшения — сохранять точное место пользователя, согласовать пример с выбранным значением и стабилизировать сетку при раскрытии меню. Действующих цветов фокуса и одной строки управления параметром достаточно для этих изменений. Вопрос рекламной паузы пользователь закрыл.

## Где и что проверено

| Условия | Пройдено в этом аудите |
| --- | --- |
| Twitch20Modern, Android TV API 36, аккаунт, настоящий Twitch | Подписки → эфир → качество → исходная карточка. Поиск с клавиатуры → Warcraft → канал → запись → скорость. Канал → клипы → Back дважды. Категории → эфир через страницу канала по удержанию OK. Переключение Overlay/кинотеатра, вход удержанием в настройки чата и часов. |
| Общие настройки на API 36 | Аккаунт в обзоре, интерфейс, включение и выключение анимации, часы, профиль Overlay, уведомления в обоих состояниях, сведения о приложении, обновления, открытие и прокрутка документа о компонентах. |
| Twitch20Release, Android TV API 30, гость, настоящий Twitch | При старте рекомендации вернули ошибку подключения. После выбора «Повторить» появились карточки и фокус. «Каналы» → «Войти» → экран получения кода → Back вернул на «Войти». В подтверждении выхода выбран пункт «Остаться». Проверены категории, настройки и рекомендации при системном шрифте 130%. |
| Плавность | Один активный AVD API 36, 1280×720, 213 dpi, SwiftShader, системный шрифт 100%. Кадровая статистика Android собрана отдельно от видеозаписи. |

Ввод — D-pad, короткий и длинный OK, Back. Подписи и фокус считаны через UI Automator, оформление проверено по нативным снимкам. AVD запущены в режиме временных изменений. Проверка экрана входа завершалась до получения нового кода. Физический ТВ, TalkBack с озвучиванием, настоящий микрофон, слышимость уведомлений, восстановление чата записи после реального обрыва и обновление приложения под аккаунтом в этот проход не входили. Полное воспроизведение клипа и все варианты ошибок внешних сервисов отдельно не проверялись.

## Дефекты и критерии исправления

| Очерёдность | Наблюдение | Что изменить и как принять |
| --- | --- | --- |
| 1. Поиск, обычный сценарий | Ввести Warcraft, открыть другой раздел и вновь выбрать «Поиск». В поле остался Warcraft, под ним надпись «Введите запрос или воспользуйтесь микрофоном», результатов нет. Подтверждено на API 36. [Экран](../evidence/ux-2026-11-17/fresh-search.png) | Если пользователь уже отправлял запрос, восстановить его выдачу и выбранный фильтр. Пустое состояние показывать для действительно пустого поля. Проверить повторный вход после успешного и пустого результата, а также Back к исходной карточке. |
| 2. Возврат из клипов, обычный сценарий | На странице Warcraft выделить «Клипы», нажать OK, затем Back. Оба раза выделялась запись под заголовком «Последние записи». Следующий OK запускал бы другой тип контента. [Перед входом](../evidence/ux-2026-11-17/clips-focus.png) · [Фокус после Back](../evidence/ux-2026-11-17/clips-return-2.txt) | Запоминать кнопку-источник наравне с карточкой. После Back повторный OK должен снова открывать клипы. После просмотра записи фокус должен по-прежнему возвращаться на эту запись. |
| 3. Потеря экрана, редкий сценарий с большим эффектом | Смена системного масштаба текста во время эфира Rubius на API 36 (100 → 115%) закрыла плеер и открыла загрузку каталога. На гостевом API 30 смена шрифта до 130% на странице категорий также сбросила раздел. В коде маршрут, история и выбранное видео живут в обычном Compose `remember`. [Каталог сразу после смены во время эфира](../evidence/ux-2026-11-17/font-change-live.png) · [Владелец маршрута](../app/src/main/java/com/oprawa/twitch20/MainActivity.kt) | Восстанавливать при пересоздании Activity идентификатор экрана, контента и путь Back. Проверить смену шрифта в эфире, на конкретной записи и внутри категории. Для записи сохранить позицию и состояние паузы. |
| 4. Пример уведомлений | При переключении «Новые эфиры подписок» в выключенное состояние подпись меняется, но тот же баннер остаётся поверх сцены. Подтверждено переключением в обе стороны на API 36. [Включено](../evidence/ux-2026-11-17/notifications-on.png) · [Выключено](../evidence/ux-2026-11-17/notifications-off.png) | В выключенном состоянии оставить саму сцену. При включении сразу показать пример баннера. Сохранить отдельную пробу звука по его переключателю. |
| 5. Стрелка обещает недоступный шаг | В крайнем значении «Предпросмотр → Со звуком» справа всё ещё яркая стрелка. Нажатие вправо ничего не меняет. Та же пара стрелок у переключателей с двумя состояниями. [После нажатия](../evidence/ux-2026-11-17/max-preview.png) | У ограниченных параметров приглушать недоступное направление. У циклических параметров оставить обе стрелки. Прямое изменение с пульта и положение текста сохраняются. |
| 6. Статусы и крупный текст | На строке «Новые эфиры подписок» показано «Включён», у «Анимации интерфейса и примеров» — «Выключен». При системном шрифте 130% в раскрытом гостевом меню «Рекомендации» сокращаются до «Рекоменда…». [Настройки](../evidence/ux-2026-11-17/animation-off.png) · [Меню с крупным текстом](../evidence/ux-2026-11-17/guest-large-rail.png) | Использовать «Вкл.»/«Выкл.» или согласовать формы с названием. В раскрытой панели дать длинному названию ширину с учётом масштаба шрифта. Проверить 100%, 115% и 130%. |
| 7. Служебные следы в оформлении | На первом открытии записей канала одновременно появляются «Обновление…» и «Загружаем…». Страница «Сторонние компоненты» выводит Markdown буквально, включая решётки, разметку таблицы и длинные адреса. [Загрузка канала](../evidence/ux-2026-11-17/channel.png) · [Документ](../evidence/ux-2026-11-17/reader.png) | Для пустого экрана оставить одно состояние загрузки, короткую пометку обновления показывать при уже видимом списке. В документе отобразить заголовки и блоки по компонентам, сохранить исходные сведения и адреса. |

Отдельное замечание по доступности из исходников. Плеер обрабатывает удержание OK на иконках чата, кинотеатра и часов, но в семантике этих кнопок публикуется только обычное нажатие. У карточек каталога для удержания есть отдельное именованное действие. Добавление такого действия в плеере стоит принять с работающим экранным диктором. ## Плавность и внешний вид

При открытии боковой панели ширина меняется с 84 до 208 dp. Каталог получает другую ширину, поэтому одновременно перемещаются и меняют размер все видимые карточки. При возврате пультом вся сетка выполняет обратное движение. На категории это особенно заметно по прямым краям постеров. [Запись переходов](../evidence/ux-2026-11-17/categories-motion.mp4) · [Узкая панель](../evidence/ux-2026-11-17/catalog-return.png) · [Раскрытая панель](../evidence/ux-2026-11-17/rail.png)

В каждом замере выполнено восемь пар нажатий с паузой 250 мс после каждой команды. Начало и конец — первая карточка «Just Chatting». Счётчики `dumpsys gfxinfo` сбрасывались перед каждым замером, UI Automator и захват видео во время замера не использовались.

| Жест | Кадры с опозданием, два прогона | 95-й процентиль времени кадра |
| --- | --- | --- |
| На соседнюю категорию и назад | 33/191 и 31/191 | 34 и 32 мс |
| Раскрыть меню и вернуться к первой карточке | 30/223 и 31/224 | 36 и 32 мс |

Диапазоны близки. Замеры показывают опоздавшие кадры в обоих маршрутах, но не устанавливают причину и не предсказывают частоту кадров на телевизоре. Главная причина предложить изменение меню сейчас — видимое изменение всей композиции. [Карточки, прогон 1](../evidence/ux-2026-11-17/row-gfx.txt) · [Прогон 2](../evidence/ux-2026-11-17/row2-gfx.txt) · [Меню, прогон 1](../evidence/ux-2026-11-17/rail-gfx.txt) · [Прогон 2](../evidence/ux-2026-11-17/rail2-gfx.txt)

**Первый визуальный эксперимент — спокойное раскрытие меню.** Оставить каталогу геометрию свёрнутой панели и раскрывать подписи поверх левого края только пока фокус в меню. Подсветку выбранного пункта включать в тот же момент, что и сейчас. Проверить быстрые ←/→, возврат к прокрученной карточке, предпросмотр закреплённого канала и режим без анимаций. Сравнить тот же маршрут и убедиться, что у вернувшей фокус карточки видна вся рамка.

**Вторая небольшая правка — читаемость плеера.** Сейчас на фокусе «Качество» разрешение видно мелко внутри иконки, а подпись расположена по центру экрана. В качестве прототипа перенести существующую подпись ближе к группе активной кнопки и сделать значение в подписи крупнее. Потребуется проверить края кадра, длинную подсказку удержания и набор кнопок в записи. [Прямой эфир](../evidence/ux-2026-11-17/live-controls.png) · [Плеер записи](../evidence/ux-2026-11-17/speed-restored.png)

**Порядок работ.** В первую итерацию взять возврат из клипов, восстановление выдачи, правдивый пример уведомлений и один прототип бокового меню. Восстановление после пересоздания Activity выделить в отдельную техническую правку с проверкой воспроизведения. Уточнение стрелок, текста и подписи плеера можно принять по снимкам до/после на тех же маршрутах.

Стоит сохранить двухколоночные настройки с мгновенным примером, фиолетовый фокус, выделение текущего качества и скорости при открытии, возврат на их кнопки и защиту выхода. В живом плеере короткий OK включил кинотеатр и отключил Overlay, удержание открыло настройки, а после возврата удалось восстановить исходный режим. Эти взаимодействия уже дают достаточную обратную связь.

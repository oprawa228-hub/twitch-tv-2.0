# Локальная проверка входа из Twitch 1.0 — 2026-11-10

## Результат

Отдельная тестовая сборка Twitch 2.0 вошла в подтверждённый пользователем аккаунт через Device Code Flow с legacy TV Client ID. KaiCenat показал видео в самом Media3-плеере. Две паузы с последующим OK и повторным MEDIA_PLAY завершились возвратом к эфиру без перезапроса источника или ошибки плеера.

**Это не доказательство постоянного отсутствия рекламы.** Начальный гостевой запуск показал commercial slate, но более поздний гостевой контроль тоже показал видео. Рекламная выдача меняется со временем. Прежний отдельный сетевой эксперимент с одновременными запросами хранится отдельно и не заменяет эту проверку APK.

## Изменения

Эксперимент включается только в debug отдельным свойством Gradle. `LegacyLiveAccess` строит запрос к фиксированному Twitch GQL endpoint и проверяет совпадение account ID в ответе до выдачи URL плееру. OAuth не передаётся на Usher или медиасегменты. HTTP-перенаправления авторизованного запроса запрещены. Ошибка аккаунта не превращается в незаметный guest fallback. VOD, clips и catalog preview остаются на прежнем пути, их авторизованное видео этим экспериментом не проверялось.

Полный lint обнаружил существующую несовместимость `ConcurrentHashMap.newKeySet` с minSdk23. Использован совместимый `Collections.newSetFromMap`, сохранив concurrent map. Также исправлены предупреждённые как ошибки точки создания FocusRequester и приведение Context к Activity. Кэш фокуса сохранён, поведение проверено отдельными Android-тестами. Локальный SDK path исправлен только в игнорируемом `local.properties`.

## Границы и следующий шаг

Физический ТВ, другие аккаунты, многочасовой просмотр, новая рекламная вставка и авторизованные VOD/clip не проверены. Успех одного канала не даёт гарантии отсутствия рекламы на других. Для публичного распространения требуется отдельно решить использование идентификатора другого клиента: Twitch требует отдельный Client ID приложения — https://dev.twitch.tv/docs/authentication/register-app/. Пока артефакт остаётся локальным экспериментом. Дальнейшая проверка устойчивости должна сравнивать guest/account одновременно при фактической рекламной вставке и сохранять ограниченные retries без фильтрации сегментов вслепую.
